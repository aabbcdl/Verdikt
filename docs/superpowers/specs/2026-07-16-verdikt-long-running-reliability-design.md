# Verdikt 长任务可靠性与安全升级设计

日期：2026-07-16
状态：已由用户“全部都做上”确认

## 目标

在不推翻现有隔离工作区、执行者、验收者和补丁应用流程的前提下，让 Verdikt 能可靠承载长时间、可恢复、分阶段、需要风险确认的编码任务，并让运行证据可复核、对比结果可重复。

## 方案选择

### 方案 A：仅修补现有缺陷

只修 resume、doctor 崩溃和锁续期。改动最小，但不能兑现重启接管、阶段验收和高风险确认。

### 方案 B：改成数据库与常驻工作进程

长期扩展性最好，但会显著增加安装、迁移和运维负担，不符合当前本地单机产品定位。

### 方案 C：持久文件驱动的渐进式升级（采用）

继续使用 `.verdikt` 作为唯一状态目录，引入原子写入的队列、运行心跳、阶段状态、审批记录、证据清单和基准轮次。无需新增外部服务，保持 CLI 与 Web 兼容，并为未来替换为数据库保留清晰边界。

## 设计

### 1. 持久任务与自动恢复

- Web 队列写入 `.verdikt/queue.json`，每次状态变化原子保存。
- 状态包含 queued、running、waiting_approval、cancelling、resumable、completed、error。
- 工作台启动时读取队列：
  - queued 重新进入队列；
  - running 若心跳已过期，转换为 resumable；
  - waiting_approval 保持等待；
  - 已完成项不重新执行。
- 每个运行保存最近心跳、当前阶段、当前动作、最近输出和下一步指令。

### 2. 真实恢复

- state.json 保存完整历史轮次或能从 iterations.jsonl 恢复。
- 保存审查者给出的下一步要求，而不是刚执行完的旧要求。
- 恢复时重新加载旧轮次参与停止判断、统计和最终总结。
- 普通异常不删除可恢复工作区；只有明确丢弃、取消或不可恢复清理才删除。
- 恢复前验证工作区、分支和起始提交仍存在；不满足时明确标记不可恢复。

### 3. 心跳、锁续期与长任务判断

- 仓库锁支持续期，并记录最后心跳与持有进程。
- Supervisor 在关键步骤和固定间隔续期。
- agent 驱动记录最近输出时间和运行阶段。
- 默认绝对超时继续保留，但到达软阈值先报告停滞信号；只有达到硬阈值才终止。
- 允许任务配置更长的 agent 超时，避免所有任务固定十分钟。

### 4. 真正的阶段验收

- TaskStage 支持自己的 acceptance、maxIterations、maxBudgetUsd、requireApproval。
- 每个阶段独立记录轮数、费用、状态和完成时间。
- 当前阶段只有在自己的验收和审查均通过后才推进。
- 无阶段任务保持原有行为。
- 高风险阶段可以进入 waiting_approval，用户确认后继续。

### 5. 高风险动作确认

- 任务支持 riskPolicy：允许、禁止、需确认的风险类别。
- 默认需要确认：部署、数据库迁移、生产访问、仓库外写入、密钥使用、外部写操作、破坏性命令。
- 执行者提示中明确禁止未批准的高风险动作。
- 支持阶段级声明和任务级预批准。
- Web/CLI 能查看、批准或拒绝待处理确认。
- 首版采用声明与命令扫描双层保护；无法可靠分类时偏向停止确认。

### 6. 可校验证据

- 每次运行完成或暂停时生成 evidence/manifest.json。
- 清单记录任务、起始提交、模型、Verdikt 版本、Node/系统环境、验收步骤、轮次文件和补丁的 SHA-256。
- 提供验证命令和 Web 接口，发现文件被改后明确报错。
- 指纹只证明证据未变化，不替代验收结论。

### 7. 可重复基准

- benchmark suite 支持 repeats、warmups 和可选 failFast。
- 每次重复使用独立运行 ID，保留单次结果。
- 汇总通过率、中位耗时、最差耗时、费用分布和结果波动。
- 记录 Verdikt 版本、项目提交、Node、系统、模型和关键配置。
- 旧 suite 默认 repeats=1，保持兼容。

### 8. 工作台稳定性

- 所有请求进入统一异常保护，任何单个接口失败只返回错误，不结束服务。
- doctor 的命令启动失败被转换成单项失败结果。
- 工作台展示持久队列、心跳、当前阶段、等待确认和可恢复原因。
- 启动时自动恢复队列；用户仍可取消、重试、继续、应用和丢弃。

## 兼容性

- 旧 task.json 无需修改。
- 旧 state.json 仍可读取，缺少新字段时使用默认值。
- 旧 benchmark suite 默认单次运行。
- CLI 命令保持原有参数，新增 approve、reject、verify-evidence。

## 主要风险与控制

- 自动恢复可能重复执行：队列操作必须幂等，运行 ID 唯一，启动前检查 summary/state。
- 高风险判断存在误报：允许任务显式预批准，但默认保守。
- 状态文件损坏：原子写入并保留最近备份，读取失败时不自动执行。
- 长任务永久占锁：心跳过期后才允许接管，不能只看创建时间。

## 验收标准

1. 服务重启后，排队任务恢复，过期运行显示可继续。
2. resume 保留历史轮次、正确下一步、正确总统计。
3. 可恢复异常不删除工作区；缺失工作区不会假装可继续。
4. 超过一小时的活跃运行仍持有锁，停止心跳后可判过期。
5. 阶段不按轮数跳转，只在当前阶段通过后推进。
6. 高风险任务进入等待确认，批准后继续，拒绝后安全停止。
7. 修改任一证据文件后，校验明确失败。
8. benchmark repeats>1 时保留每次结果并输出分布。
9. doctor 遇到权限错误时工作台仍在线。
10. 构建、格式、测试、安全、打包、压力和编辑器插件检查全部通过。
